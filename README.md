# 画笺

画笺是面向 SillyTavern 1.14.x–1.18.x 的 GPT / OpenAI-compatible 与 NovelAI 双引擎生图扩展。AI 回复完成后，它会识别 `<draw>...</draw>`，在消息原位置显示生图卡片，也可仅对本次会话中新完成的 AI 消息自动生图。

从 1.1.0 起，默认使用“免服务端直连”模式：只需在 SillyTavern 的扩展安装窗口粘贴仓库链接，不需要 Termux 命令，也不需要启用 Server Plugins。

## 一键安装

在 SillyTavern 的“安装扩展”中填写：

```text
https://github.com/phyllis-0612/st-image-atelier
```

安装完成后刷新页面或重启 SillyTavern。扩展菜单中会出现「✦ 画笺」，状态应显示「免服务端模式已就绪」。

也可以点击聊天输入框左下角的魔法棒按钮，在展开菜单中选择「画笺」快速打开。

## 首次配置

设置页顶部可以随时切换「GPT / OpenAI」与「NovelAI」。切换后只会使用当前引擎的配置，两套密钥和预设互不覆盖。

### GPT / OpenAI-compatible

1. 保持运行模式为「免服务端直连（推荐，一键安装）」。
2. 在「API 预设」旁点击「新建」，自定义名称；填写 Base URL 和 API Key。
3. 在「模型」一栏点击旁边的「拉取模型」，然后从下拉框选择生图模型。
4. 点击「保存预设」。以后可直接用顶部预设下拉框快速切换整组 URL、Key 与模型。
5. 可点击「测试模型接口」确认模型列表接口；生图接口会在实际生成时单独验证。
6. 修改「默认尺寸 / 质量 / 数量」后点击「保存生图参数」，保存后的值会用于下次生图。如果 `<draw>` 显式带有 `ratio` 或 `quality`，标签参数优先。质量从低到高为 `low` / `medium` / `high` / `xhigh` / `max`，其中 `xhigh` 和 `max` 只有 `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst` 支持，其他 GPT Image 模型最高 `high`。
7. 让 AI 回复：

```xml
<draw ratio="portrait" quality="high" count="1">
雨夜霓虹街道中的电影感人像
</draw>
```

默认手动点击生成；自动生图默认关闭。

### NovelAI

1. 切换到「NovelAI」。NAI 固定使用免服务端直连，不需要 Server Plugin。
2. 在「NAI 中转站 / 兼容站 URL」填写中转地址，在「中转站 Key / NAI Token」填写中转站分配的 Key。官方 NovelAI 与原生兼容站默认以 `Authorization: Bearer <Key>` 请求 `/ai/generate-image`；地址也可直接填写完整生图端点。Aurora 中转填写以 `/api` 或 `/api/v1` 结尾的地址即可，插件会自动归一化到实际的 `/api/generate-direct` 流式端点。
3. 选择 NAI 模型、尺寸、采样器、步数、Prompt Guidance、种子与负面提示词。
4. 在「画师串预设（每套独立正面 + 负面）」中新建并命名风格串；每套预设分别保存自己的正面和负面画师串。紧邻预设选择器的「预设分享（JSON）」可导出当前或全部非空预设，也可导入别人分享的 JSON；完全重复项会自动跳过，同名但内容不同的预设会自动改名。生成时正面按「该预设正面串 → 标签正文 → 模型质量标签」拼接，负面按「该预设负面串 → 可选的全局附加负面词」拼接，不会修改聊天原文。
5. 点击「保存 NovelAI 配置」。此后手动和自动生图都会使用当前 NAI 模型与画师串预设。

NAI 中转站 Key / NovelAI Token 与 GPT API Key 分开保存在当前酒馆账户存储中，不会写入扩展设置、聊天消息或图片元数据。中转站既可返回 NovelAI 原生 ZIP 图片包，也可返回常见 JSON/Base64 图片结构或 Aurora 的 NDJSON 流；插件会统一解析、补全相对图片地址，并逐张保存到酒馆图片目录。官方接口同样兼容：站点填写 `https://image.novelai.net` 即可。

NAI 中转站需要兼容 NovelAI 的原生生图请求体（`input`、`model`、`action`、`parameters`），并允许 SillyTavern 页面来源进行 CORS 跨域访问。若中转站只提供 OpenAI `/v1/images/generations` 格式，请改用「GPT / OpenAI」引擎；这种接口不是 NAI 原生协议，是否支持 NAI 专属采样参数取决于中转站。

## 主要能力

- 一条消息可含多个独立 `<draw>` 标签。
- 标签会在正文中的原位置直接替换成生图卡片；即使酒馆净化器移除了标签本身、只留下提示词，也会按提示词定位替换。正文完成后延迟追加的标签同样会实时识别。
- 同一标签可反复生成；每张卡最多留最近 10 张，更早的会自动删除（收藏的不删），画廊照常保留其余规则。
- 生图失败或尚未生成的卡片可一键「删除」，连同消息里的 `<draw>` 标签和元数据一起清掉，不留痕迹。
- 可选开启「允许临时修改提示词后重绘」：从上一张图实际使用的基础提示词继续改，只作用于下一次生成，不修改聊天正文或原标签；NovelAI 可同时临时调整负面提示词。
- 自动生图只给「这次打开页面之后才出现」的标签：酒馆刚收到的新回复，或之后才贴进正文的生图段、改过的提示词（由 DOM 变化即时触发，低频扫描兜底），而且出现的那一刻自动生图得开着。已经有图、有过任何一次生成的不自动画；刷新网页、翻旧楼、换聊天再切回来、之后才打开开关，都不会让旧楼重新出图。自动生图使用固定 `auto:<tagId>`，同一个标签不会提交两次。
- URL 与 Base64 返回都会立即上传到当前 SillyTavern 用户的图片目录。
- 多 API 命名预设、独立密钥、模型下拉选择与快速切换。
- GPT / OpenAI-compatible 与 NovelAI 双引擎一键切换；NAI 支持独立站点、Token、模型和常用生成参数。
- 可命名、新建、删除、快速切换及通过 JSON 导入导出包含独立正面/负面内容的 NovelAI 画师串预设，并保留每张图实际使用的模型、画师预设与随机种子元数据。
- 画师串分享 JSON 只包含名称与正负面内容，不导出 API Key、NAI Token、内部 ID 或时间戳。
- 默认请求 `b64_json` 内嵌返回，不依赖浏览器二次下载图床 URL；可选开启「生成失败后智能重试」，在上游明确拒绝可选参数时只回退并重试一次。
- 生图失败会显示上游 HTTP 状态和经过脱敏的真实错误原因。
- 若上游内容审核拒绝提示词，会明确显示审核原因，不再混用参数不支持提示。
- 紧凑的五态消息卡片、分区设置页与双列响应式画廊。设置页最上面是快捷开关（自动生图、当前预设、当前角色的参考图组），状态提示贴在面板底边，在长页面哪一段操作都看得到结果。出图后的卡片上「参考重画」旁边有「换预设」，不进设置页也能换当前预设（NovelAI 时是当前画师串）。
- 已有图片重新生成时会立即切换到“正在重新生成”加载动画，完成后再展示新图。
- 生成中的卡片右上角显示已用时间（如「已用 42 秒」「已用 1 分 05 秒」），每秒更新；出图后「✓ 已完成」旁边留着这张图的总用时（如「用时 16 分 37 秒」），图片上不压任何东西。
- 出图后卡片下方显示这张图用的预设、画质、模型和尺寸；画质是实际发给上游的值。
- 同一张卡画过好几张时，用信息下面的「‹ 上一张　2 / 4　› 下一张」直接在卡片上翻看，信息跟着正在看的那张。
- 出图后的「参考重画」拿这张图当参考再画（走 `/v1/images/edits`），人脸、服装跟着它；参考图组里可以放最多 4 张角色参考图，每个角色卡记住自己用哪组，每张图自动带上。
- 「查看提示词」展开后下面有「一键复制」（原图查看层里也有），复制的是这张图实际用的提示词；手机用局域网 http 地址打开酒馆时也能复制。
- 出图后的「重新生成」可以当场选用哪个预设（「原渠道」排第一），不用打开设置面板，也不改设置里的当前预设。
- 等不及时点生成中卡片上的「↻ 再画一张」：有好几个 API 预设时可以换一个（换 key、换分组）马上再 roll，正在画的那张留在后台接着画，卡片上显示「后台还有 1 张在画 · 已用 18 分 30 秒」。后台那张画好后放进这张卡的历史和画廊，不会顶掉新出的图。
- 预设的「超时」默认 1 小时、最多 2 小时，慢的分组排队十几二十分钟也能等到。
- 重 roll、滑到另一版或切走聊天时还在画的图不会丢：照常画完存进画廊；被滑走的放回那一版回复，滑回去就能看到，不再显示「生成被中断」。
- 内置方图、竖图和横图的常用尺寸（包括 `512x768`、`576x1024`、`1024x576` 等），以及 2K / 4K（`2048x2048`、`4096x4096`、`2160x3840`、`3840x2160` 等；能不能出看模型和中转站）；尺寸值会在请求前自动把 `×`、`X` 或 `*` 统一为接口要求的小写 `x`。图片上限 64 MB。
- 正文图片和画廊图片均可点击进入酒馆内的原图查看层；手机可直接长按保存，右上角固定关闭按钮、页面返回键和底部关闭按钮都能回到原聊天。
- 支持图片文件分享的系统会额外显示“分享 / 保存”按钮，不再把不稳定的自动文件下载作为移动端主流程。
- 时间倒序画廊每张图标出渠道和画质（「GPT · 预设名」+ 画质，或「NAI · 画师串名」），一眼看出是哪条线路画的；「只看这个聊天」一键只留当前聊天的图（聊天改过名也认得），点开后「跳到所在楼层」直接回到那张图所在的楼；格子里放缩略图（长边 768 的 JPEG，存在酒馆的 `st-image-atelier-thumbs/` 目录），点开看图、下载、参考重画都是原图，原图一个字节不动；1.9.0 之前的图翻到时后台补，也可在设置页一次补全；支持持久收藏、提示词搜索、组合筛选、批量收藏/删除/下载与元数据真删；进入批量模式后可直接点缩略图或文字区选图。支持按保留天数或保留张数自动清理旧图，收藏图片不参与自动清理。画廊元数据和生成记录都独立保存在当前 ST 用户文件中，不撑大 `settings.json`，也不撑大聊天文件：楼层里只留图片引用。
- 日间、夜间和跟随酒馆三种主题模式；表单输入区使用独立高对比前景色与背景色。
- 可选 Server Plugin 增强模式保留服务端密钥、进程锁和独立 JSON 元数据。

## 主题与画廊清理

设置页的「界面与画廊」区域可选择「跟随酒馆主题」「日间模式」或「夜间模式」。主题切换会立即保存并应用到设置面板、消息生图卡片、画廊和原图查看层。

画廊清理提供两条可独立启用的规则：

- 按时间：删除早于自定义天数的图片，例如清理 7 天前的图片；
- 按数量：只保留最新的自定义张数，例如仅保留近 200 张。

两条规则同时启用时采用“任一命中即清理”，并始终从最旧图片开始。保存规则时会先确认并立即检查一次；之后在扩展启动、成功生成图片、打开画廊以及页面保持开启期间的每小时维护中自动检查。清理只处理画笺自己登记的本地图片，不会扫描或删除酒馆及其他扩展的图片。删除不可撤销，失败的文件会保留记录并在下次检查时重试。

收藏图片会同时排除在按时间与按数量清理之外；仍可手动删除，但会再次明确确认。画廊的搜索与筛选读取全部轻量元数据，图片本身仍只渲染当前页。桌面端可批量发起下载；移动浏览器常会阻止多文件下载，此时插件会保留选择并提示逐张打开原图后长按保存。

## 聊天里只留引用（2.0.0）

聊天文件里每一楼的 `extra.stImageAtelier` 只放一条引用：`{ messageUuid, tagIds }`，一个标签约 100 字节。提示词在正文的 `<draw>` 里本来就有，不再复制一份；标签的状态（提示词指纹、当前显示哪张、图片引用、自动生图 / 删除抑制两个标记）记在按聊天分的侧文件 `user/files/st-image-atelier-chat-<聊天名>-<指纹>.json` 里（走酒馆的 `/api/files/upload`，和画廊元数据同一套接口，多设备共用、跟着酒馆走），按 `tagId` 记，打开聊天时读一次。生成记录在 `st-image-atelier-attempts.json`（每张卡最多 20 条、整份最多 2000 条），图片元数据在 `st-image-atelier-gallery.json`。Base64、原始 API 响应、提示词的复制品一律不进聊天，也不放 `extension_settings`。

出图、删图、自动清理、超上限硬删、自动生图的标记都只写侧文件，不保存聊天；聊天只在出现新标签、你删标签、「整理旧数据」时才动一次。侧文件内容和上次写的一样就不写，文档里没有时间戳、随机数，页面重开、切回聊天、切后台回来都不会多写一次。用小锚看：聊天放着不动十分钟，「当前」页不该冒出新快照；要是有，点快照旁的「改了什么」看是哪个字段在变。

标签的身份不依赖侧文件：侧文件读不到（没写上、聊天改了名、分支出来的聊天）时按位置认回楼里原来的 ID，图按画廊里的记录接回卡片，不会给整楼换新 ID、也不会重写聊天。2.0.0～2.0.2 在这种情况下会把图从卡片上弄掉；2.0.3 起加载聊天时会按「同一楼、同一段提示词」把挂在旧 ID 上的图认领回来。页面转入后台或要关掉时，还在等合并写的记录会立刻写掉。

2.0.0 之前的版本把标签状态（1.7.0 之前还有整份生成记录和图片记录）写在每一楼里，楼层一多聊天文件就几十 MB，酒馆每次保存都整份上传、重写、备份。旧聊天打开时状态会自动搬进侧文件（聊天一个字不动，图照常看），再到设置页「界面与画廊」最下面点「整理旧数据」一次搬完：

- 遍历所有楼层和滑动存档里的副本：旧版的生成记录搬进独立文件、整份图片记录补回画廊，画廊索引里没有的引用按路径核对文件（在的补回画廊、不在的去掉），每张卡最多留最近 10 张图（收藏的不删），状态写进侧文件，每一楼换成引用，然后只保存一次聊天；
- 点之前先算账并确认，建议先用小锚「立即快照」或导出一份聊天；打开聊天时发现还有旧格式的楼也会提醒一次；
- 重复执行没有副作用；执行前后在控制台输出该聊天 tags 的总字节数，面板状态行显示整理前后的大小。

1.7.1 起插件的保存并进酒馆的 `saveChatDebounced`：同一秒里不管酒馆还是插件要存，整份聊天只写一次盘，也错开了出图返回、正文写完那一瞬间的高峰（只有「整理旧数据」仍当场写完）。2.0.0 起出图根本不保存聊天。画廊元数据和生成记录文件延后一两秒合并写；上游给的 base64 原样上传，不再整张解码再重编码；哪张卡的状态变了只重画那一张。1.8.3 起生成期间撤掉聊天 DOM 监听（酒馆吐字时不再逐帧收变动记录），图片异步解码，触屏设备上不做毛玻璃。1.9.0 起画廊格子用缩略图，一屏不再解码几十张原图。

## 画廊索引拆成小文件（2.4.0）

画廊索引（每张图的提示词、路径、收藏……）和生成记录以前各是一整份文件，改一条就整份重新上传：画廊一千张图时，出一张图要上传二十多 MB 的索引和记录，每次打开页面还要整份下载一遍。2.4.0 起各拆成「一份清单 + 若干小文件」，改哪张图只重写它所在的那一小份（最多 160 KB），上传量和画廊总共多大无关；打开页面时没变的小文件不重新下载。

| 画廊里已有 | 2.3.0 出一张图上传的索引和记录 | 2.4.0 |
| --- | --- | --- |
| 300 张，提示词 9 KB | 8.5 MB | 平均 0.24 MB，最多 0.48 MB |
| 1000 张，提示词 9 KB | 28.1 MB | 同上 |
| 3000 张，提示词 9 KB | 82.6 MB | 同上 |
| 1000 张，提示词 3 KB | 12.4 MB | 同上 |

- 升级后第一次打开自动在后台拆分，不用点什么。拆完之前一切照旧工作，拆不成也照旧能用；设置页「外观与维护 → 数据文件」写着现在是拆开的还是整份的，没拆成会写出原因。旧的两份文件（`st-image-atelier-gallery.json`、`st-image-atelier-attempts.json`）留在原地当备份，不再读写。
- 多设备：写之前先看服务器上那一份有没有被别的设备动过，别的设备加的记录原样带上。开了很久没刷新的页面不会再把别的设备后来出的图从画廊里盖掉。
- 没变的小文件靠浏览器本机的缓存（IndexedDB）免下载；缓存只是缓存，清掉、用不了都只是多下载一遍，不影响对错。
- 文件都在酒馆的 `user/files` 下：`st-image-atelier-gallery-index.json`（清单）、`st-image-atelier-gallery-m0001.json`…（分片）；生成记录是 `st-image-atelier-attempts-…`。

## 参考图（图生图）

GPT / OpenAI-compatible 这边可以带参考图，走 OpenAI 的 `/v1/images/edits` 接口（中转站要支持）：

- **参考图组（垫图）**：设置页独立的「参考图组」区块。组是全局的，不跟 API 预设走，换渠道不用重传；每组最多 4 张，传几张角色的脸和服装。每个角色卡可以记住自己用哪一组（「当前角色出图用」），换卡自动换脸；没单独设置的角色用默认组，也可以设成「不带参考图」。「每张图自动带上参考图」和「高保真参考（input_fidelity: high）」跟着组走。每张缩略图下面有「换一张」（原位替换，顺序不变，满 4 张也能换）和「删除」。
- **卡片上「参考重画」**：出图后拿这张图当参考再画，剧情连着走脸不变；有几个预设时先选。指定的那张排最前，再带这个角色那组里的，合起来最多 4 张。
- **从相册另选一张**：「参考重画」里可以换成相册里的图当参考，用完就删。

参考图存在酒馆自己的 `st-image-atelier-refs` 目录，组里只记路径；生成记录和画廊记录上也只记路径。1.10.0 之前记在预设上的参考图会自动迁成组（同样几张只留一组，当前预设那组是默认组），文件不动。只有免服务端直连的 GPT 有，NovelAI 和增强模式暂不支持。

## 临时重绘与智能重试

「允许临时修改提示词后重绘」和「生成失败后智能重试」均默认关闭，可在插件设置中独立开启。前者不会保存未提交的草稿，也不会改写 `<draw>`；后者每次生成最多增加一次请求，仅处理错误信息明确点名的 `response_format`、`size`、`quality` 或 `n` 参数。内容审核、API Key/权限、余额/配额、429、网络/CORS、超时、连接中断、取消、5xx 与未知错误都只显示真实原因并保留手动重试，不会自动再次请求。

## 备用线路

设置页「API 预设」下面可以选一个已有的预设当「备用线路」（全局一条，建议挑稳定的那家）。主线路（这次出图用的预设）失败时：

- 报错弹窗里多一个「⇄ 换「备用线路名」重画」，失败的卡片上也有「⇄ 换备用线路」，点了照原请求换备用线路重画；
- 「再画一张」的选预设列表里，备用线路标「（备用）」排在前面；
- 审核拦截不给换（换了也照样被拦），这次用的本来就是备用线路时也不给。

另有开关「主线路挂了自动换备用线路」（默认关）：只在连不上、上游 5xx、限流、密钥或余额出问题时自动换一次，不弹报错，卡片上会写明换了线路；超时不自动换，免得中转站那边还在画、两边都扣钱。备用线路目前只在免服务端模式的 GPT 下可用。

## 报错弹窗

「报错弹窗」开关默认开启，可在插件设置里关闭。开启时各类报错都会弹出一个小弹窗，点一下任意位置就关；在弹窗里拖选文字可以复制报错。

- 生图失败：连不上服务器、请求超时、内容被审核拦截（含中转站 HTTP 200 里写的 unsafe、违规等）、密钥或权限问题、限流、上游 5xx、图片下载或保存失败等，标题直接写是哪一类，内容与卡片上的报错一致。
- 生图失败的那条带「↻ 重新生成」键，点了按原请求重跑，不用再滑到卡片上点；不想重跑就点别处关掉。
- 本次请求的 `quality` 是 `xhigh` / `max` 且上游返回 400 / 422 时，会额外提示只有 gpt-image-2.5 系列支持。
- 智能重试去掉 `quality`、`size` 或 `n` 后才出图时也会弹窗，说明这张图按上游默认值生成。
- 「返回格式不兼容」会写明收到的顶层字段和前 600 字（密钥脱敏），截图发给中转站就能说清楚。常见的非标准形状（`images` 字段、顶层单张、纯链接数组、聊天接口里的 Markdown 图等）会直接认出来。
- 把生图做成异步任务的中转（第一次只回任务记录，`assets` 为空、`execution_mode: "async"`）也认：画笺拿着任务 id 每隔几秒去问（优先用它给的 `poll_url`，没有就按生图地址加任务 id），画完了照常存；最多等到预设的超时，卡片上会写「中转站在后台排队画」。
- 设置页按钮操作失败（如测试模型接口）、画廊加载 / 收藏 / 删除失败、连不上 Server Plugin、读不到聊天里的生图数据、增强模式下生成被中断等也会弹。
- 重 roll、滑走或切走聊天后，上一版还在画的图画好了会提醒一声（「上一版回复的图画好了」），说明图放在哪，带「⌕ 查看」键直接看原图；没画成的照样弹报错并注明是上一版的图，但不带「重新生成」（卡片已经不在眼前）。
- 「再画一张」之后留在后台的那张画好了也会提醒（「后台那张也画好了」），带「⌕ 查看」；没画成的注明是后台那张，不带「重新生成」。

用户手动取消不弹；画廊自动清理等后台维护失败只记在浏览器控制台。弹窗开着时再来的报错会合并到同一个弹窗，内容相同只累计次数。

## 免服务端模式的网络要求

浏览器会直接请求中转站，因此中转站必须允许 SillyTavern 页面来源进行 CORS 跨域访问。若模型接口测试提示“浏览器无法连接”，请检查：

- Base URL 是否正确；
- 手机能否访问该地址；
- 中转站是否返回 `Access-Control-Allow-Origin`；
- HTTPS 页面是否请求了被浏览器拦截的 HTTP 地址。

API Key 保存在当前 SillyTavern 账户的前端账户存储中，不写入聊天消息、图片元数据、日志或 Git 仓库。由于请求发生在浏览器中，其他同源前端扩展理论上仍可访问请求数据；高安全需求请使用可选 Server Plugin 模式。

如果生成接口能连接，但返回的临时图片 URL 被 CORS 阻止，请在高级设置把「图片返回格式」设为 `b64_json`（新安装默认如此），让兼容中转站直接返回 Base64。

## 可选增强模式

仓库仍包含 `server-plugin/`。它适用于不支持 CORS 的中转站，或必须把完整 Key 与生成幂等锁留在服务端的部署。安装方法见 [docs/INSTALLATION.md](docs/INSTALLATION.md)。普通用户无需安装。
